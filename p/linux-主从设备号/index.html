ls -l

在 Linux 上随便看一眼 /dev，会看到一类“文件”长得非常奇怪：

1
2
3
4

crw-rw-rw- 1 root root    1,   3  /dev/null
crw-rw-rw- 1 root root    1,   5  /dev/zero
crw-rw-rw- 1 root tty     5,   0  /dev/tty
brw-rw---- 1 root disk    8,   0  /dev/sda

第一个字母 c 是字符设备（character device），b 是块设备（block device）。 普通文件的位置上不再是文件大小，而是两个逗号隔开的数字——主设备号（major number）和 从设备号（minor number）。/dev/null 的 1, 3 表示“主号 1、从号 3”。

这两个数字是整个 Linux 设备驱动体系的路由地址：没有它们，open("/dev/null") 就不知道要把 这次打开操作交给内核里的哪个驱动函数。本文要回答的问题就是：

  • 这两个数字在内存里到底是什么样的一个量（dev_t）？
  • 内核用哪一段代码把它们“翻译”成驱动（MAJOR/MINOR/MKDEV、cdev_map、chrdev_open）？
  • 驱动怎么申请/占用一段号（register_chrdev_region / alloc_chrdev_region / cdev_add）？
  • mknod、/proc/devices、ls -l 这些用户态入口和内核的关系？

用一个 236 行不到的演示内核模块，把这些问题全部实测一遍，再回到源码逐行解释。

dev_t

首先，内核里“设备号”根本不是一个结构体，而是一个 32 位无符号整数，类型名 dev_t：

include/linux/types.h:18-21：

1
2
3

typedef u32 __kernel_dev_t;
...
typedef __kernel_dev_t		dev_t;

一个 u32 怎么装下两个数字？bit 复用：高 12 位是主号，低 20 位是从号。20 位来自内核 对“从号上限”的定义 MINORBITS（后面会看到历史原因）：

1
2
3
4
5
6
7

dev_t (u32, 32 bit)
┌──────────────────────────┬────────────────────────────┐
│      主号 major (12 bit)  │       从号 minor (20 bit)   │
│    dev >> MINORBITS(20)   │    dev & MINORMASK(0xFFFFF) │
└──────────────────────────┴────────────────────────────┘
    理论范围 0 ~ 4095            理论范围 0 ~ 1048575
    字符驱动实际 < 512            MINORMASK = 2^20 - 1

例如动态分配得到的 dev_t = 250609672：

1
2

250609672 = 239 × 2^20 + 8
          = 239 : 8            （十进制写法：主号 239，从号 8）

MAJOR / MINOR / MKDEV：拆包与打包

负责这个“拆包/打包”的是三个宏，定义在 include/linux/kdev_t.h:7-12：

1
2
3
4
5
6

#define MINORBITS	20
#define MINORMASK	((1U << MINORBITS) - 1)

#define MAJOR(dev)	((unsigned int) ((dev) >> MINORBITS))
#define MINOR(dev)	((unsigned int) ((dev) & MINORMASK))
#define MKDEV(ma,mi)	(((ma) << MINORBITS) | (mi))
  • MAJOR(dev)：右移 20 位取出主号（250609672 >> 20 = 239）；
  • MINOR(dev)：与 0xFFFFF（1048575）相与取出从号（250609672 & 1048575 = 8）；
  • MKDEV(ma, mi)：反向打包（(239 << 20) | 8 = 250609672）。

同一个文件里还提供了一组“历史格式”互转函数（kdev_t.h:24-81）：old_valid_dev() 判断 主/从号是否都小于 256（即能否放进老的 16 位编码）；old_encode_dev / new_encode_dev / new_decode_dev / huge_encode_dev 用于系统调用边界上的编码转换，后面讲 mknod/stat 时还要用到它们。

一个小知识：dev_t 能表达的主号其实有 12 位（0~4095），但字符设备注册时内核还额外 限制 major < 512（CHRDEV_MAJOR_MAX，include/linux/fs.h:2983）， 校验代码在 fs/char_dev.c 的 __register_chrdev_region() 里，后文会看到。

内核态与用户态：两套宏

有意思的是，在用户态可见的 UAPI 头文件里，还保留着一套 8 位的旧宏：

include/uapi/linux/kdev_t.h（#ifndef __KERNEL__ 分支内）：

1
2
3

#define MAJOR(dev)	((dev)>>8)
#define MINOR(dev)	((dev) & 0xff)
#define MKDEV(ma,mi)	((ma)<<8 | (mi))

这是 Linux 2.4 时代的遗产：当时 dev_t 是 16 位，主号、从号各 8 位。2001 年 2.5 内核把 dev_t 扩成 32 位后，从号位宽从 8 涨到 20，但老宏被保留给那些“直接 include 内核头文件算 设备号”的远古用户态程序——注释里写得明明白白：

1
2
3
4

/*
Some programs want their definitions of MAJOR and MINOR and MKDEV
from the kernel sources. These must be the externally visible ones.
*/

如果哪位读者在项目里看到 dev >> 8 这种写法，请立刻意识到：那是 8 位时代的老黄历， 自己写的驱动一律用 include/linux/kdev_t.h 的 20 位版本。用错了会怎样？比如主号 239 （0xEF），按 8 位算：239 >> 8 = 0，239 & 0xff = 239——主号被算成了 0，直接错乱。

而 mknod 这类系统调用在“用户态传数字”和“内核存 dev_t”之间，用的是另一组编码函数 （new_encode_dev/new_decode_dev，见后文「从 mknod 到 chrdev_open」一节）。

主号管驱动，从号管实例

为什么需要两个号？因为设备分两层组织：

  • 主号：标识“谁（哪个驱动）来服务”。一个驱动通常占一个主号，/proc/devices 里 “主号 + 名字”就是这张对照表。
  • 从号：标识“这个驱动下的哪一个实例/子设备”。同一个驱动经常要管很多个长得一样、 行为略不同的设备，就用从号区分。

三个经典例子：

设备 主:从 同一个驱动，从号在干什么
/dev/null 1:3 mem 驱动（主号 1）下几十个“哑设备”之一：null/zero/full/random…各占一个从号
/dev/tty0 4:0 tty 驱动（主号 4）管理所有终端，每个虚拟控制台一个从号
/dev/sda 8:0 sd 驱动（主号 8）管理所有 SCSI 磁盘，每个磁盘及其分区各占一个从号（sda1 是 8:1，sdb 是 8:16）

为什么需要一个“全文件只有两处用、还自称会死”的指针？因为它服务的是一种特殊的 cdev 所有权模型。现代两步式写法里，cdev 是驱动自己的东西——嵌在驱动的结构体里 （本实验的 struct demo_dev 就内嵌了 struct cdev cdev），驱动自己调 cdev_add() / cdev_del()，注册表条目（kzalloc 清零）里的 cd->cdev 永远是 NULL，谁也不碰。 但老式一键 API register_chrdev() 的封装 __register_chrdev()（fs/char_dev.c:268-300） 走的是另一条路：它在基础设施内部 cdev_alloc() + cdev_add() 建好 cdev，驱动 从头到尾拿不到这个指针；卸载时驱动只还给内核一个主号和一个名字 （unregister_chrdev(major, name)），内核必须自己记得“这个主号段的 cdev 是我建的、 长什么样”，否则没法销毁——cd->cdev 就是记在注册记录上的“内部自建 cdev 账本指针”。

理解了所有权模型，/* will die */ 的含义就清楚了：这个字段存在的唯一理由就是服务 注定被淘汰的 register_chrdev() 家族。上游已经把老 API 收敛成一个内联包装 （include/linux/fs.h:3000），并引导驱动改走 register_chrdev_region() + cdev_add() 或驱动模型（cdev_device_add()）；等某天真把 register_chrdev() 移除，这个字段连同 __unregister_chrdev() 里的条件删除逻辑可以一并删掉。注释敢写 “will die”，是上游对 “过渡期残留”的官方自述——它同时提醒到：一条职责边界：注册表只管“谁占用了哪些号”， 不该管 cdev 的生命周期。这条边界正是 2.5 时代 dev_t 扩到 32 位、引入 cdev 与 分段注册时，从“一张表直接存每个主号的 name + fops”（2.4 及更早的设计）拆分出来的。

顺带一个隐患：cd->cdev 是裸指针，而注册表条目不会随模块卸载自动清理。若驱动用了 老 API 却忘了配对 unregister_chrdev()，条目和它指向的 cdev 会一起泄漏——与 「坑与教训」一节的幽灵段同源，只是这边多漏一个 cdev 对象。

拆解：

  • ① 主号校验：major >= 512 直接 -EINVAL，并打印一条 pr_err—— 实验 4d 里 register_chrdev_region(MKDEV(512,0), 1, ...) 触发，dmesg 里能看到 CHRDEV "demo-toobig" major requested (512) is greater than the maximum (511)。
  • ② 从号段校验：baseminor + minorct - 1 不得超过 MINORMASK（1048575）。
  • ⑤ 动态主号：major == 0 表示“请内核帮我挑一个空闲主号”，挑法见下一节。
  • ⑥ 冲突检测：桶内链表按主号排好序。对同主号的相邻段比较区间：
    • 已有段整体在请求段左边（baseminor + minorct <= baseminor）→ 继续往后看；
    • 已有段整体在请求段右边（baseminor >= baseminor + minorct）→ 到此为止， 不冲突，可以插入（同一主号下互不重叠的多段可以共存）；

int register_chrdev_region(dev_t from, unsigned count, const char *name)
{
	struct char_device_struct *cd;
	dev_t to = from + count;
	dev_t n, next;

	for (n = from; n < to; n = next) {
		next = MKDEV(MAJOR(n)+1, 0);      /* 下一个主号的开头 */
		if (next > to)
			next = to;
		cd = __register_chrdev_region(MAJOR(n), MINOR(n),
			       next - n, name);
		if (IS_ERR(cd))
			goto fail;
	}
	return 0;
fail:
	to = n;
	for (n = from; n < to; n = next) {
		next = MKDEV(MAJOR(n)+1, 0);
		kfree(__unregister_chrdev_region(MAJOR(n), MINOR(n), next - n));
	}
	return PTR_ERR(cd);
}

核心是那个 for 循环：next = MKDEV(MAJOR(n)+1, 0) 把每次迭代截断在当前主号的末尾， 一段跨主号的请求会被自动拆成多个 (major, baseminor, minorct) 段，每段都完整经过 __register_chrdev_region() 的校验与冲突检测；失败时按已注册的子段回滚。

{
	const struct file_operations *fops;
	struct cdev *p;
	struct cdev *new = NULL;
	int ret = 0;

	spin_lock(&cdev_lock);
	p = inode->i_cdev;                    /* 第一次打开时 i_cdev 为空 */
	if (!p) {
		struct kobject *kobj;
		int idx;
		spin_unlock(&cdev_lock);
		kobj = kobj_lookup(cdev_map, inode->i_rdev, &idx);   /* 按设备号查 cdev */

			return -ENXIO;

		   we dropped the lock. */

		if (ret)
			goto out_cdev_put;

这就是“打开路由”的真相：

  1. 用 inode->i_rdev（例如 239:8）到 cdev_map 里查：kobj_lookup() 找到覆盖该 设备号的 probe（drivers/base/map.c:95-133），命中条件就是区间包含： if (p->dev > dev || p->dev + p->range - 1 < dev) continue;，且返回 *index = dev - p->dev（map.c:118）——也就是从号在段内的偏移；
  2. 查到的 kobj 用 container_of 还原成 struct cdev，缓存到 inode->i_cdev（第二次 open 不再查表）；
  3. 用 cdev_get() 把模块引用计数 +1（try_module_get，char_dev.c:348-359）—— 这就是“设备文件被打开时模块不能 rmmod”的机制（实验第 8 步验证）；
  4. 把 struct file 的 f_op 换成驱动自己的 ops（replace_fops），再调用驱动的 open()。此后该文件描述符上的 read/write 等全部直达驱动。

查不到对应 cdev（没注册、没 cdev_add 的号段）时返回 -ENXIO——用户态看到 No such device or address，这就是实验第 7 步 236:7 报错的原因。

顺带一提：查不到时 chrdev_open 之前还留了一手“模块自动加载”——cdev_map 初始时 每桶都挂了一个 base probe（kobj_map_init(base_probe, ...)，char_dev.c:674）， 兜底逻辑是 request_module("char-major-%d-%d", MAJOR(dev), MINOR(dev)) （char_dev.c:666-672）。如果某个驱动在 modules.alias 里声明了 char-major-N-M 别名，udev/modprobe 会在打开瞬间把它自动拉起来。

现代姿势：device_create + devtmpfs

上面的链路里有个繁琐环节：驱动注册了号段、挂了 cdev，还得有人去 mknod 建节点。 现代内核（udev + devtmpfs + sysfs）把这步也自动化了。关键是把设备号交给驱动模型里的 struct device（它有 devt 字段），然后 device_create() 注册设备：

	dev = device_create(demo_class, NULL,
			    MKDEV(dyn_major, DYN_BASEMINOR + i),
			    NULL, "demo-dyn%d", i);

device_create() 内部调用 device_add()，会发生三件事：

  • 在 sysfs 的 /sys/class/<class>/<name>/ 下生成条目，其中 dev 文件内容就是 "主号:从号"（用户态脚本可用它反推 mknod 参数，busybox mdev 就是这么干的）；
  • 发出 uevent，udev 按规则设置权限、建软链接等；
  • devtmpfs 监听到设备注册，直接在 /dev 下自动创建节点——不需要任何人手写 mknod。

实验里 ls -l /dev/demo-dyn* 立刻能看到 239, 8 等四个自动节点，而模块卸载时 device_destroy() 让 devtmpfs 自动删除节点。对比手动 mknod 的 /dev/demo-fix*： rmmod 后 inode 依然存在（devtmpfs 不知道要删它），只是再打开会 -ENXIO。 两相对照，就能理解为什么现代驱动推荐 cdev_device_add()（fs/char_dev.c:544-561） 把 cdev 和 device 的生命周期绑在一起管理。

#define DYN_COUNT	4	/* 动态主号 : 8 .. 11 */

/* 一组连续小号 = 一个"逻辑设备"(注册段 + 一个 cdev) */
struct demo_dev {
	dev_t		first;		/* 段内第一个设备号 dev_t */
	unsigned int	baseminor;	/* 段起始小号 */
	unsigned int	count;		/* 段内小号个数 */
	const char	*tag;		/* 打印用标识 */
	struct cdev	cdev;
	atomic_t	open_cnt;
};

static struct demo_dev dyn_dev = { .tag = "dynamic" };	/* alloc_chrdev_region 动态主号 */
static struct demo_dev fix_dev = { .tag = "fixed" };	/* register_chrdev_region 固定主号 */
static bool dyn_active, fix_active;
static struct class *demo_class;

static int fixmajor = 236;
module_param(fixmajor, int, 0444);
MODULE_PARM_DESC(fixmajor, "register_chrdev_region 要占用的固定主号(0 = 跳过固定主号部分)");

/* ------------------------- fops ------------------------- */

static int demo_open(struct inode *inode, struct file *filp)
{
	struct demo_dev *dd = container_of(inode->i_cdev, struct demo_dev, cdev);
	unsigned int idx = iminor(inode) - dd->baseminor;

	/* chrdev_open 已经用 cdev_map 按 (主,从) 号路由到正确的 cdev,
	 * 走到这里说明该小号一定落在 cdev_add(dev, count) 区间内 */
	atomic_inc(&dd->open_cnt);
	filp->private_data = dd;
	pr_info("%s: open %-7s dev=%u:%u (iminor=%u, idx=%u, open_cnt=%d)\n",
		DEVNAME, dd->tag, imajor(inode), iminor(inode),
		iminor(inode), idx, atomic_read(&dd->open_cnt));
	return 0;
}

static int demo_release(struct inode *inode, struct file *filp)
{
	struct demo_dev *dd = filp->private_data;

	if (dd)
		atomic_dec(&dd->open_cnt);
	return 0;
}

static ssize_t demo_read(struct file *filp, char __user *buf,
			 size_t len, loff_t *off)
{
	struct demo_dev *dd = filp->private_data;
	char tmp[192];
	int n;

	if (!dd || *off)
		return 0;

	n = snprintf(tmp, sizeof(tmp),
		     "demo(%s): first dev_t=%u  major=%u minor=%u  (baseminor=%u count=%u)\n"
		     "          打开次数 open_cnt=%d\n",
		     dd->tag, (unsigned int)dd->first,
		     MAJOR(dd->first), MINOR(dd->first),
		     dd->baseminor, dd->count, atomic_read(&dd->open_cnt));
	if (n > (int)len)
		n = len;
	if (copy_to_user(buf, tmp, n))
		return -EFAULT;
	*off = n;
	return n;
}

static const struct file_operations demo_fops = {
	.owner		= THIS_MODULE,
	.open		= demo_open,
	.release	= demo_release,
	.read		= demo_read,
};

/* ------------------------- 工具函数 ------------------------- */

static void demo_dev_init(struct demo_dev *dd, dev_t first,
			  unsigned baseminor, unsigned count)
{
	dd->first = first;
	dd->baseminor = baseminor;
	dd->count = count;
	atomic_set(&dd->open_cnt, 0);
	cdev_init(&dd->cdev, &demo_fops);
	dd->cdev.owner = THIS_MODULE;
}

/* 打印一次 register_chrdev_region 的返回码 */
static int try_register(dev_t from, unsigned count, const char *name)
{
	int ret = register_chrdev_region(from, count, name);

	pr_info("  register_chrdev_region(%s, %u:%u, count=%u) -> %d\n",
		name, MAJOR(from), MINOR(from), count, ret);
	return ret;
}

/* ------------------------- init / exit ------------------------- */

static int __init devnum_demo_init(void)
{
	dev_t dyn_first, d1, d2;
	unsigned dyn_major;
	int ret, i;

	pr_info("== %s: MINORBITS=%d, MINORMASK=0x%x, CHRDEV_MAJOR_MAX=%d\n",
		DEVNAME, MINORBITS, MINORMASK, CHRDEV_MAJOR_MAX);

	/* ---------- (1) alloc_chrdev_region: 动态主号 ---------- */
	ret = alloc_chrdev_region(&dyn_first, DYN_BASEMINOR, DYN_COUNT,
				  "demo-dyn");
	if (ret < 0) {
		pr_err("%s: alloc_chrdev_region(dyn) failed: %d\n", DEVNAME, ret);
		return ret;
	}
	dyn_major = MAJOR(dyn_first);
	pr_info("(1) alloc_chrdev_region(&dev, baseminor=%u, count=%u, \"demo-dyn\")\n"
		"    -> dev_t=%u  = %u:%u\n", DYN_BASEMINOR, DYN_COUNT,
		(unsigned int)dyn_first, dyn_major, MINOR(dyn_first));

	/* ---------- (2) 连续 alloc 两次: 观察动态主号从高到低扫 ---------- */
	ret = alloc_chrdev_region(&d1, 0, 1, "demo-order-A");
	pr_info("(2) alloc#2 -> dev_t=%u = %u:%u (ret=%d)\n",
		(unsigned int)d1, MAJOR(d1), MINOR(d1), ret);
	ret = alloc_chrdev_region(&d2, 0, 1, "demo-order-B");
	pr_info("    alloc#3 -> dev_t=%u = %u:%u (ret=%d)\n",
		(unsigned int)d2, MAJOR(d2), MINOR(d2), ret);
	unregister_chrdev_region(d1, 1);
	unregister_chrdev_region(d2, 1);
	pr_info("    unregister #2/#3 -> 主号 %u、%u 归还\n",
		MAJOR(d1), MAJOR(d2));

	/* ---------- (3) register_chrdev_region: 固定主号 ---------- */
	if (fixmajor > 0) {
		dev_t base = MKDEV(fixmajor, FIX_BASEMINOR);

		ret = try_register(base, FIX_COUNT, "demo-fixed");
		if (ret < 0) {
			pr_err("%s: 固定主号 %u 被占用, 请换 fixmajor=\n", DEVNAME, fixmajor);
			unregister_chrdev_region(dyn_first, DYN_COUNT);
			return ret;
		}
		pr_info("(3) 固定主号段 %u:%u..%u 注册成功\n",
			fixmajor, FIX_BASEMINOR, FIX_BASEMINOR + FIX_COUNT - 1);

		/* 4a: 与已有段重叠 -> -EBUSY */
		ret = try_register(MKDEV(fixmajor, 1), 4, "demo-ovl");
		pr_info("     ^ 与 %u:0..2 重叠, 预期 -16 (EBUSY)\n", fixmajor);
		/* 4b: 同主号、不重叠的小号段 -> 允许共存 */
		ret = try_register(MKDEV(fixmajor, 200), 1, "demo-disj");
		pr_info("     ^ 与已有段不重叠, 预期 0; 随后立即释放\n");
		if (!ret)
			unregister_chrdev_region(MKDEV(fixmajor, 200), 1);
		/* 4c: 一段跨越主号边界 -> register_chrdev_region 内部自动拆成两段 */
		ret = try_register(MKDEV(fixmajor, MINORMASK - 1), 4,
				   "demo-xmajor");
		pr_info("     ^ %u:1048574 + count=4 会跨到 %u:0..1, 预期 0\n",
			fixmajor, fixmajor + 1);
		if (!ret) {
			ret = try_register(MKDEV(fixmajor + 1, 0), 1,
					   "demo-xmajor-probe");
			pr_info("     ^ 再占 %u:0 应失败(预期 -16): 证明第二段确实被占了\n",
				fixmajor + 1);
			unregister_chrdev_region(MKDEV(fixmajor, MINORMASK - 1), 4);
			pr_info("     一次 unregister 会把两段(两个主号)都释放\n");
		}
		/* 4d: 主号 >= 512 -> -EINVAL */
		ret = try_register(MKDEV(CHRDEV_MAJOR_MAX, 0), 1, "demo-toobig");
		pr_info("     ^ 主号 %d >= CHRDEV_MAJOR_MAX(512), 预期 -22 (EINVAL)\n",
			CHRDEV_MAJOR_MAX);
		/* 4e: 小号段越界 -> -EINVAL。
		 * 注意: 走 register_chrdev_region() 时越界范围会被"跨主号拆分"消化掉
		 * (见上面 4c), 所以这里改用不做拆分的 alloc_chrdev_region() 触发 */
		{
			dev_t tmp;

			ret = alloc_chrdev_region(&tmp, MINORMASK, 2, "demo-minoor");
			pr_info("     ^ alloc_chrdev_region(baseminor=%u(MINORMASK), count=2) "
				"小号段越界, 预期 -22 (EINVAL), 实得 %d\n",
				(unsigned int)MINORMASK, ret);
		}
	} else {
		pr_info("(3) fixmajor=0: 跳过固定主号部分\n");
	}

	/* ---------- (5) cdev_add: 让设备号段真正可被打开 ---------- */
	demo_dev_init(&dyn_dev, dyn_first, DYN_BASEMINOR, DYN_COUNT);
	ret = cdev_add(&dyn_dev.cdev, dyn_first, DYN_COUNT);
	if (ret < 0) {
		pr_err("%s: cdev_add(dyn) failed: %d\n", DEVNAME, ret);
		unregister_chrdev_region(dyn_first, DYN_COUNT);
		return ret;
	}
	dyn_active = true;
	pr_info("(5) cdev_add(dyn): %u:%u..%u -> %d\n", dyn_major,
		DYN_BASEMINOR, DYN_BASEMINOR + DYN_COUNT - 1, ret);

	if (fixmajor > 0) {
		demo_dev_init(&fix_dev, MKDEV(fixmajor, FIX_BASEMINOR),
			      FIX_BASEMINOR, FIX_COUNT);
		ret = cdev_add(&fix_dev.cdev, MKDEV(fixmajor, FIX_BASEMINOR),
			       FIX_COUNT);
		if (ret < 0) {
			pr_err("%s: cdev_add(fixed) failed: %d\n", DEVNAME, ret);
			cdev_del(&dyn_dev.cdev);
			dyn_active = false;
			unregister_chrdev_region(dyn_first, DYN_COUNT);
			unregister_chrdev_region(MKDEV(fixmajor, FIX_BASEMINOR),
						 FIX_COUNT);
			return ret;
		}
		fix_active = true;
		pr_info("    cdev_add(fixed): %u:%u..%u -> %d\n", fixmajor,
			FIX_BASEMINOR, FIX_BASEMINOR + FIX_COUNT - 1, ret);
	}

	/* ---------- (6) 现代路径: class + device_create ----------
	 * 每个 device 带上 devt; udev 收到 uevent 后/devtmpfs 自动建节点,
	 * 不需要手写 mknod, /sys/class/demo_dyn/ 下也有 dev=主:从 文件
	 */
	demo_class = class_create("demo_dyn");
	if (IS_ERR(demo_class)) {
		pr_err("%s: class_create failed\n", DEVNAME);
		goto err_class;
	}
	for (i = 0; i < DYN_COUNT; i++) {
		struct device *dev;

		dev = device_create(demo_class, NULL,
				    MKDEV(dyn_major, DYN_BASEMINOR + i),
				    NULL, "demo-dyn%d", i);
		if (IS_ERR(dev)) {
			pr_err("%s: device_create demo-dyn%d failed\n",
			       DEVNAME, i);
			goto err_devs;
		}
	}
	pr_info("(6) device_create x%d -> /dev/demo-dyn0..%d 由 devtmpfs 自动生成\n",
		DYN_COUNT, DYN_COUNT - 1);

	pr_info("== %s ready\n", DEVNAME);
	pr_info("   固定主号: %u:%u..%u   (手动 mknod 演示)\n",
		fixmajor, FIX_BASEMINOR, FIX_BASEMINOR + FIX_COUNT - 1);
	pr_info("   动态主号: %u:%u..%u  (device_create 自动节点)\n",
		dyn_major, DYN_BASEMINOR, DYN_BASEMINOR + DYN_COUNT - 1);
	return 0;

err_devs:
	while (i-- > 0)
		device_destroy(demo_class,
			       MKDEV(dyn_major, DYN_BASEMINOR + i));
	class_destroy(demo_class);
	demo_class = NULL;
err_class:
	if (fix_active) {
		cdev_del(&fix_dev.cdev);
		fix_active = false;
	}
	if (dyn_active) {
		cdev_del(&dyn_dev.cdev);
		dyn_active = false;
	}
	unregister_chrdev_region(dyn_first, DYN_COUNT);
	if (fixmajor > 0)
		unregister_chrdev_region(MKDEV(fixmajor, FIX_BASEMINOR),
					 FIX_COUNT);
	return -EIO;
}

static void __exit devnum_demo_exit(void)
{
	int i;
	unsigned dyn_major = MAJOR(dyn_dev.first);

	if (demo_class) {
		for (i = 0; i < DYN_COUNT; i++)
			device_destroy(demo_class,
				       MKDEV(dyn_major, DYN_BASEMINOR + i));
		class_destroy(demo_class);
		pr_info("== %s: device_destroy x%d + class_destroy -> /dev/demo-dyn* 自动消失\n",
			DEVNAME, DYN_COUNT);
	}
	if (dyn_active) {
		cdev_del(&dyn_dev.cdev);
		dyn_active = false;
	}
	if (fix_active) {
		cdev_del(&fix_dev.cdev);
		fix_active = false;
	}
	unregister_chrdev_region(dyn_dev.first, DYN_COUNT);
	if (fixmajor > 0)
		unregister_chrdev_region(MKDEV(fixmajor, FIX_BASEMINOR),
					 FIX_COUNT);
	pr_info("== %s: cdev_del x2 + unregister_chrdev_region x2 -> 主号 %u、%u 全部归还\n",
		DEVNAME, dyn_major, fixmajor);
}

module_init(devnum_demo_init);
module_exit(devnum_demo_exit);

逐条对照源码解读：

  • (1) 动态主号：alloc_chrdev_region() 返回 dev_t=250609672，即 239:8。 为什么是 239？find_dynamic_major() 从 254 往下扫，而 240~254 全被系统驱动占用， 于是第一个空闲主号是 239。注意我们故意让 baseminor=8（不从 0 开始）， 为了证明“从号可以任意偏移”。
  • (2) 连续分配顺序：第二、第三次 alloc 依次拿到 238:0、237:0——主号从高往低 一个个发，用完立即 unregister 归还。
  • (3) 固定主号：register_chrdev_region(236:0, count=3) 成功。
  • (4a) 重叠段：再注册 236:1 起 4 个，与已有 236:0..2 重叠 → -16（-EBUSY）。 这正是 __register_chrdev_region() 第 ⑥ 步区间比较的结果。
  • (4b) 同主号不重叠段：236:200 起 1 个 → 成功（之后主动释放），证明注册表 支持同一主号下多个互不重叠的段。
  • (4c) 跨主号拆分：236:1048574 起 4 个 → 成功。这段跨越主号边界，被 register_chrdev_region() 自动拆成 236:1048574..1048575 与 237:0..1 两段； 随后再抢 237:0 得到 -EBUSY，反向证明第二段确实被占了。注意一次 unregister_chrdev_region() 也按同样逻辑把两段都释放。
  • (4d)(4e) 越界：主号 512（>= CHRDEV_MAJOR_MAX）和 baseminor=1048575, count=2 分别返回 -22（-EINVAL）。日志里那两行 CHRDEV "..." ... 不是我们打印的， 是内核 __register_chrdev_region() 自己的 pr_err（源码第 ① ② 步）。 值得一提：4e 故意用 alloc_chrdev_region() 而不是 register_chrdev_region()—— 后者会把越界范围先拆成多个合法段（见 4c），根本走不到越界校验。
  • (5)(6)：两段 cdev_add 让设备可打开；device_create 为动态主号建了 4 个 devtmpfs 自动节点。

观察点：

  • ls -l 的第 5 列就是主:从号（十进制），它来自 statx 的 stx_rdev_major/minor（fs/stat.c:735-736）；
  • stat -c %t/%T 是十六进制：ef = 239，b = 11；
  • 自动节点名字 demo-dyn0 与从号 8 并不对应——节点编号 0 的从号是 8， 因为 baseminor=8；从号 ≠ 数组下标的证明就在这里；
  • sysfs 的 dev 文件内容就是 主:从 字符串，可被用户态脚本解析后反哺 mknod （mdev/udev 的常见手法）；
  • 手动 mknod 的节点没有 sysfs 条目、没有权限管理、卸载后无人清理——这正是 device_create() 要解决的问题。

设备号泄漏

之前，有写一段用 register_chrdev_region(MKDEV(236,1048575), 2) 做 “从号越界”测试的代码，测试完忘了 unregister。结果 rmmod 之后：

模块都卸载了，/proc/devices 里却永久残留着两条“幽灵”记录——因为模块卸载只执行 exit 函数里写的 unregister_chrdev_region()，内核不会自动清扫 chrdevs[]。 这两段号直到重启前都无法再被任何驱动使用（再注册会 -EBUSY），这就是设备号泄漏。

恢复手段：unregister_chrdev_region()只按(major, baseminor, minorct)` 三元组精确匹配，不校验注册者，所以可以写一个一次性模块“替别人”释放：

static int __init ghost_clean_init(void)
{
	/* 当初 register_chrdev_region(MKDEV(236,1048575), 2) 被拆成两段:
	 * (236,1048575,1) + (237,0,1)。反向 unregister 也要给原始 count=2,
	 * unregister_chrdev_region() 内部会同样跨主号拆分匹配。 */
	unregister_chrdev_region(MKDEV(236, 1048575), 2);
	pr_info("ghost_clean: unregistered leaked ranges 236:1048575 + 237:0\n");
	return -EPERM;	/* 一次性任务, 主动卸载 */
}

实测可被清掉：
$ sudo insmod ./ghost_clean.ko
$ cat /proc/devices | grep minoor    # 空 = 已清理

它同时带出一个知识点：“拆成几段”和“一次注册”是一对——注册用 register_chrdev_region(MKDEV(236,1048575), 2)（跨主号拆两段），释放也必须用 count=2 的同样调用，否则只清得掉第一段

类似地，还有几个常见教训：

  • register_chrdev() 老接口一次注册 256 个从号，除非确实需要，否则别用；
  • 用 alloc_chrdev_region() 拿动态主号时，主号是内核挑的，用户态建节点前必须把 主号传出去（/proc/devices、module param、sysfs 均可）；
  • 从号数组下标 ≠ 从号本身——baseminor 可以是任意值，务必用 iminor - baseminor 做下标，我们的实验特意用 baseminor=8 演示这一点；
  • 字符、块主号表独立，同号可并存；但同一张表内冲突是绝对的，跨驱动“借号” 前先查 /proc/devices。

   inode->i_rdev = dev_t                    # 设备号住进 inode
   inode->i_fop  = def_chr_fops             # open 先走通用打开器

   chrdev_open(): kobj_lookup(cdev_map, i_rdev)  → cdev      (fs/char_dev.c:386)

        │
        ▼  replace_fops(filp, 驱动自己的 ops) → demo_open()
   iminor(inode) = 0                        # 驱动按从号路由实例
        │
        ▼  ls -l /dev/demo-fix0             # statx: MAJOR/MINOR(i_rdev)
   "236, 0"                                 # 十进制主:从

全部要点：

  • dev_t 是一个 32 位整数：高 12 位主号、低 20 位从号（MINORBITS=20）， MAJOR/MINOR/MKDEV 就是拆包与打包；
  • 主号选驱动、从号选实例；字符、块注册表彼此独立，数字可重复；
  • chrdevs[]（注册表）管“占用与冲突”，cdev_map（kobj_map）管“打开路由”， 两张表独立，注册 ≠ 可打开，可打开 ≠ 已注册；
  • register_chrdev_region() 会把跨主号的段自动拆分，alloc_chrdev_region() 从 254 往下找空闲主号；
  • mknod 把数字存进 inode->i_rdev，open 经 def_chr_fops.chrdev_open 按 设备号查到 cdev、换成驱动 fops、再调驱动 open；
  • 现代驱动用 device_create()/cdev_device_add() 让 devtmpfs+udev 自动建节点、 自动管理权限，手动 mknod 是“考古模式”；
  • 设备号是全局有限资源：注册/释放必须成对，泄漏的号段在重启前无法复用。
