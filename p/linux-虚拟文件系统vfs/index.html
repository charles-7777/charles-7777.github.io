全景图：VFS 四大对象与两座"桥"

Linux 的虚拟文件系统（VFS）用四个核心结构体把"一个文件"拆成四个不同维度：

结构体 定义位置 它回答的问题
struct super_block include/linux/fs.h:1446 这个文件系统实例是谁？块大小、挂载在哪个设备？
struct inode include/linux/fs.h:793 这个文件本身是谁？大小、权限、数据块在哪？
struct dentry include/linux/dcache.h:92 这个路径名是什么？/a/b/c 的层级与缓存？
struct file include/linux/fs.h:1211 这个打开会话是什么？当前读写偏移、操作函数表？

它们之间的关系可以浓缩成一句话：

file ──(f_path.dentry)──▶ dentry ──(d_inode)──▶ inode ──(i_sb)──▶ super_block
   └──(f_inode)───────────────┘                   │(i_mapping)      │(s_bdev)
                                                  ▼                 ▼
                                           address_space        block_device
                                                  │                 │
                                          页缓存(folio)  ◀──▶  磁盘 Block

而这一切要能"动起来"，还需要另外两个维度把它们挂到进程上：

  • 进程 → 文件：task_struct->files（files_struct 文件描述符表）→ struct file；
  • 进程 → 命名空间：task_struct->nsproxy（nsproxy）→ mnt_namespace（挂载命名空间）→ mount 树 → super_block；
  • 进程 → 当前路径：task_struct->fs（fs_struct 的 root/pwd）决定相对路径、根目录从哪开始解析。

这两座"桥"——磁盘桥（inode ↔ block）和进程桥（进程 ↔ namespace）——正是本文「关键一问」与「进程视角」两章的主题。

内核注释里对这四个对象的经典描述（include/linux/fs.h 附近）： VFS 把"文件名→文件内容"的解析拆成 dentry（名字）与 inode（内容/元数据）两层， 这样 open("/a/b/c") 时绝大部分路径组件只需要在内存 dcache 中命中，而不必访问磁盘。

要点：

  1. 一个"种类"的文件系统 ≠ 一个 super_block。ext4 是一个 file_system_type，但每挂载一个 ext4 分区就有一个 super_block 实例。同类型的所有 sb 通过 file_system_type->fs_supers 哈希链表串起来（include/linux/fs.h:2704）。
  2. s_blocksize 是磁盘 I/O 的最小单位，比如 4096 字节。它与 s_blocksize_bits（12）配合：1 << s_blocksize_bits == s_blocksize。
  3. s_root 指向根目录 dentry，它又指向根 inode。ext4 挂载时用 ext4_iget(sb, EXT4_ROOT_INO, ...) 读入 inode 2（根目录）作为 s_root（见 fs/ext4/super.c:5518）。
  4. s_fs_info 是"私有数据"指针。ext4 挂载时把它指向 struct ext4_sb_info，内核宏 EXT4_SB(sb) 就是 container_of 反推：

这是内核"面向对象"手法的核心：公共部分（super_block）在前，私有部分（ext4_sb_info）通过指针/内嵌关联。struct ext4_inode_info 也用了同样的手法，把 struct inode vfs_inode 内嵌为最后一个字段（fs/ext4/ext4.h:1114），这样 EXT4_I(inode) = container_of(inode, struct ext4_inode_info, vfs_inode)。

几个必须记住的点：

  • i_ino 是磁盘上的 inode 编号（ext4 里就是 1、2、3…），ls -i 显示的就是它。
  • i_size 是逻辑大小，i_blocks 是物理占用的 512 字节块数（du 命令读它）。
  • i_mapping 默认指向内嵌的 i_data——inode_init_always() 里 inode->i_mapping = mapping;（fs/inode.c:295），其中 mapping 就是 &inode->i_data。i_data 是 struct address_space，它管着这个文件在页缓存里的所有 folio。i_mapping 就是"inode ↔ 内存页"的桥，而内存页又通过块映射指向磁盘块。
  • i_dentry 是"别名链表头"：一个 inode 可以被多个名字引用（硬链接），每个名字对应一个 dentry，dentry 通过 d_alias 挂进来。这就是 d_alias 与 i_dentry 配对的原因（struct dentry 的 d_u.d_alias，include/linux/dcache.h:128）。
  • i_fop 是"文件操作表"（ext4 是 ext4_file_operations），open 时被拷贝/引用到 struct file->f_op。

路径上的各级目录是怎么串起来的

把 open("/home/charles/vfslab/a.txt") 拆开看，这条路径的每一级并不是一个"字符串"，而是一串对象，链在两个世界里同时存在：

① 磁盘世界：目录数据块里的"记录链"

每个目录在磁盘上就是一个 inode，它的数据块里按顺序躺着一条条定长/变长的目录项记录 ext4_dir_entry_2——每条记录 = (inode 号, 名字长度, 名字)。所以磁盘上的链是：

1

根目录 inode(2) 的数据块 ──"home"──▶ inode 57346 的数据块 ──"charles"──▶ inode 42 ...

解析时内核调 inode->i_op->lookup（ext4 是 ext4_lookup，fs/ext4/namei.c），它用 ext4_find_entry 顺着目录数据块把 (名字 → inode 号) 找出来，再 ext4_iget 把下一级的 inode 读进内存。

② 内存世界：dcache 树 + nameidata 游标

目录项被读进内存后，VFS 用一个 struct dentry 代表每一级名字，并织成树：

  • 向上：dentry->d_parent 指向父目录的 dentry（dcache.h:97）；
  • 横向：dentry->d_sib 挂进父的 d_children 链表（dcache.h:122-123）；
  • 名字→inode：dentry->d_inode（dcache.h:102），由 d_instantiate() 绑定；
  • 回到文件系统：dentry->d_sb（dcache.h:109）声明这一级属于哪个 super_block。

一处目录最多能存多少条目？—— 磁盘上限与内存上限

“存目录项的地方"其实有两处，上限完全不同：

① 磁盘上：一个目录 inode 的数据块（持久上限，受 ext4 格式约束）

目录项记录 struct ext4_dir_entry_2（fs/ext4/ext4.h:2409）= 8 字节头部（4B inode + 2B rec_len + 1B name_len + 1B file_type）+ 名字，4 字节对齐：

项目 数值 依据
单个名字长度 ≤ 255 字节 NAME_MAX（include/uapi/linux/limits.h:12）、EXT4_NAME_LEN
单条记录最大 8+255 → 264 字节（对齐后） ext4_dir_rec_len
一个 4K 块能放 1 字名 ~341 条 / 255 字名 ~15 条 4096 / 对齐后记录长
索引块容量 根 ~508、节点 ~510 条 dx_entry（每条 8B） dx_root_limit/dx_node_limit（fs/ext4/namei.c:577/588）
htree 深度 兼容 2 层 / largedir 3 层 EXT4_HTREE_LEVEL_COMPAT=2、EXT4_HTREE_LEVEL=3（ext4.h:2646）
理论整目录上限 兼容模式 ~17 万条；largedir ≈ 508×510≈25.9 万叶子块 × 每块 ~333 条 ≈ 千万级 上面两行相乘
目录子目录数 ≤ 65000（无 dir_nlink 特性时） EXT4_LINK_MAX（ext4.h:328）EXT4_DIR_LINK_MAX
软限制 挂载选项 max_dir_size_kb，默认 0=不限 s_max_dir_size_kb（fs/ext4/namei.c:61）

所以：老格式 ext3/ext4 目录到几万~几十万文件就会因 htree 打满而变慢/告警，largedir 特性（ext4 4.4+ 默认开启）把上限推到千万级。

② 内存里：dcache 没有条数上限，只有内存约束

  • 每个 struct dentry 约 200~300 字节（短名内联在 d_shortname，长名单独分配）。
  • d_children 是链表、dcache 哈希表按内存量分配桶（alloc_large_system_hash("Dentry cache", ...)，fs/dcache.c:3220），桶数只影响查找速度，不影响容量。
  • 总量由内存压力 + shrinker 回收（sb->s_dentry_lru），/proc/sys/fs/dentry-state 的前两列是 nr_dentry/nr_unused——第三列的 45 是回收用的"年龄阈值（秒）"，不是条数上限，别被误导。

物理块号 pblk 是"文件系统块号"，要换算成设备扇区：sector = pblk << (blkbits - 9)（4K 块 → 左移 3）。

/* vfsmap.c — 把"文件逻辑块 → 磁盘物理块"的映射打出来
 * 即内核 ext4_map_blocks() 在用户态可见的等价结果 (FS_IOC_FIEMAP) */

#include <string.h>

#include <unistd.h>
#include <sys/ioctl.h>
#include <sys/stat.h>

{

	int fd = open(argv[1], O_RDONLY);
	if (fd < 0) { perror("open"); return 1; }

	if (fstat(fd, &st) < 0) { perror("fstat"); return 1; }

	printf("== struct inode 的部分字段 (fstat) ==\n");
	printf("  i_ino       = %lu\n", (unsigned long)st.st_ino);
	printf("  i_size      = %lld 字节\n", (long long)st.st_size);
	printf("  i_blocks    = %lld 个 512B 块 (物理占用)\n", (long long)st.st_blocks);
	printf("  i_nlink     = %lu\n", (unsigned long)st.st_nlink);
	printf("  块大小      = %u 字节 (st_blksize, 即 i_blkbits=log2(%u))\n", blk, blk);
	printf("  i_atime     = %ld  i_mtime = %ld  i_ctime = %ld\n",
	       (long)st.st_atime, (long)st.st_mtime, (long)st.st_ctime);
	printf("\n== ext4_map_blocks 的结果: 逻辑块 → 物理块 (FS_IOC_FIEMAP) ==\n");
	printf("  逻辑块号(lblk)  物理块号(pblk)  长度(块)  标志\n");

	struct fiemap *fm = calloc(1, sizeof(*fm) + 128 * sizeof(struct fiemap_extent));
	if (!fm) { perror("calloc"); return 1; }
	fm->fm_start = 0;
	fm->fm_length = st.st_size;
	fm->fm_extent_count = 128;
	if (ioctl(fd, FS_IOC_FIEMAP, fm) < 0) { perror("FS_IOC_FIEMAP"); return 1; }
	struct fiemap_extent *ex = (struct fiemap_extent *)(fm + 1);
	for (unsigned i = 0; i < fm->fm_mapped_extents; i++) {
		printf("  %12llu   %14llu   %8llu   0x%x%s\n",
		       ex[i].fe_logical / blk, ex[i].fe_physical / blk,
		       ex[i].fe_length / blk, ex[i].fe_flags,
		       (ex[i].fe_flags & FIEMAP_EXTENT_LAST) ? "  <- 最后一块" : "");
	}
	printf("  (pblk 换算扇区: pblk << %u = 第 %llu 个 512B 扇区)\n",
	       __builtin_ctz(blk / 512), (unsigned long long)(ex[0].fe_physical / 512));
	free(fm);
	close(fd);
	return 0;
}

/* vfsdup.c — 演示 struct file / struct dentry / struct inode 的区分 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>

static void show_fd_path(int fd)
{
	char link[64], buf[256];
	snprintf(link, sizeof(link), "/proc/self/fd/%d", fd);
	ssize_t n = readlink(link, buf, sizeof(buf) - 1);
	if (n < 0) { perror("readlink"); return; }
	buf[n] = 0;
	printf("    /proc/self/fd/%d -> %s\n", fd, buf);
}

int main(int argc, char **argv)
{
	const char *path = (argc > 1) ? argv[1] : "a.txt";

	int wfd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
	write(wfd, "0123456789ABCDEF", 16);	/* 写长一点方便演示 f_pos */
	close(wfd);

	int fd1 = open(path, O_RDONLY);
	int fd2 = open(path, O_RDONLY);
	struct stat s1, s2;
	fstat(fd1, &s1);
	fstat(fd2, &s2);
	printf("1) 同一文件 open 两次:\n");
	printf("    fd1=%d  fd2=%d\n", fd1, fd2);
	printf("    inode(fd1)=%lu  inode(fd2)=%lu → 共享同一个 struct inode? %s\n",
	       (unsigned long)s1.st_ino, (unsigned long)s2.st_ino,
	       (s1.st_ino == s2.st_ino) ? "YES" : "NO");
	printf("    但它们是两个 struct file: 各自有独立的 f_pos\n");

	char b1[16] = {0}, b2[16] = {0};	/* 留足空间给 NUL */
	read(fd1, b1, 8);			/* fd1 的 f_pos: 0 -> 8 */
	read(fd2, b2, 8);			/* fd2 的 f_pos: 0 -> 8 (互不影响) */
	printf("    fd1 读到 \"%s\"  (f_pos 0→8)\n", b1);
	printf("    fd2 读到 \"%s\"  (自己的 f_pos 也从 0 开始)\n", b2);

	printf("\n2) struct file->f_path 记住的 dentry (经 /proc/self/fd):\n");
	show_fd_path(fd1);
	show_fd_path(fd2);

	printf("\n3) unlink 之后: dentry 被删, inode 仍靠 file 引用存活\n");
	char tmp[64];
	snprintf(tmp, sizeof(tmp), "%s.del", path);
	int fd3 = open(tmp, O_WRONLY | O_CREAT | O_TRUNC, 0644);
	write(fd3, "ghost", 5);
	unlink(tmp);
	printf("    unlink(\"%s\") 后 /proc/self/fd/%d 仍然可读, 显示:\n", tmp, fd3);
	show_fd_path(fd3);
	struct stat s3;
	fstat(fd3, &s3);
	printf("    fstat 仍然成功 → inode #%lu 还活着 (i_count>0)\n",
	       (unsigned long)s3.st_ino);
	close(fd3);
	printf("    close(fd3) 后 inode 才被 evict\n");
	close(fd1); close(fd2);
	return 0;
}

/* vcache.c — 直接测量"页缓存"(address_space->i_pages) 的占用
 * posix_fadvise(POSIX_FADV_DONTNEED) = 内核 mapping->invalidate_folio 一路 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>

static long meminfo_cached_kb(void)
{
	FILE *f = fopen("/proc/meminfo", "r");
	char line[128];
	long kb = -1;
	while (fgets(line, sizeof(line), f))
		if (sscanf(line, "Cached: %ld kB", &kb) == 1) break;
	fclose(f);
	return kb;
}

int main(int argc, char **argv)
{
	if (argc < 2) { fprintf(stderr, "用法: %s <文件>\n", argv[0]); return 1; }
	int fd = open(argv[1], O_RDONLY);
	struct stat st;
	fstat(fd, &st);
	printf("文件: %s  (inode %lu, 大小 %.1f MB)\n", argv[1],
	       (unsigned long)st.st_ino, st.st_size / 1048576.0);

	posix_fadvise(fd, 0, 0, POSIX_FADV_DONTNEED);	/* 从"不在缓存"开始 */
	long c0 = meminfo_cached_kb();
	printf("\n[1] 清缓存后 Cached 基线          : %ld kB\n", c0);

	char buf[65536];
	ssize_t n;
	while ((n = read(fd, buf, sizeof(buf))) > 0) ;	/* 读一遍 → 填页缓存 */
	long c1 = meminfo_cached_kb();
	printf("[2] cat 一遍后 Cached           : %ld kB  (+%ld kB ≈ 文件大小 → 全部进页缓存)\n",
	       c1, c1 - c0);

	lseek(fd, 0, SEEK_SET);
	while ((n = read(fd, buf, sizeof(buf))) > 0) ;	/* 再读一遍 */
	long c2 = meminfo_cached_kb();
	printf("[3] 再 cat 一遍后 Cached        : %ld kB  (增量≈0 → 命中缓存, 不再读盘)\n", c2);

	posix_fadvise(fd, 0, 0, POSIX_FADV_DONTNEED);	/* 逐出该文件所有 folio */
	long c3 = meminfo_cached_kb();
	printf("[4] fadvise(DONTNEED) 后 Cached : %ld kB  (-%ld kB ≈ 文件大小 → 页被逐出)\n",
	       c3, c2 - c3);
	close(fd);
	return 0;
}

/* vfsns.c — 命名空间身份证: ns_common.inum */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

static long ns_inum(const char *path)
{
	char buf[128];
	ssize_t n = readlink(path, buf, sizeof(buf) - 1);
	if (n < 0) return -1;			/* 权限受限等 */
	buf[n] = 0;
	unsigned long v = 0;
	sscanf(buf, "%*[^:]:[%lu]", &v);	/* 解析 "mnt:[4026532211]" */
	return (long)v;
}

static void print_ns_inum(const char *label, const char *path)
{
	long v = ns_inum(path);
	if (v < 0)
		printf("  %-8s: (读取失败, 权限受限)  %s\n", label, path);
	else
		printf("  %-8s: %lu   (%s)\n", label, v, path);
}

int main(void)
{
	setvbuf(stdout, NULL, _IONBF, 0);	/* fork 子进程会继承 stdout 缓冲, 关掉避免错乱 */

	printf("== 本进程 (PID %d) 各命名空间的 inum ==\n", getpid());
	print_ns_inum("mnt", "/proc/self/ns/mnt");
	print_ns_inum("pid", "/proc/self/ns/pid");
	print_ns_inum("net", "/proc/self/ns/net");
	print_ns_inum("uts", "/proc/self/ns/uts");

	long my_mnt = ns_inum("/proc/self/ns/mnt");
	printf("\n== 与其他进程比较 ==\n");
	print_ns_inum("PID 1", "/proc/1/ns/mnt");
	printf("  (读取他人 ns 需要 ptrace 权限 → 无权限时 EACCES, 这也是安全机制之一)\n");

	pid_t shell = fork();
	if (shell == 0) {
		execl("/bin/sh", "sh", "-c",
		      "echo \"  子 shell (PID $$): mnt inum = $(readlink /proc/self/ns/mnt)\"",
		      (char *)NULL);
		_exit(1);
	}
	waitpid(shell, NULL, 0);

	pid_t child = fork();
	if (child == 0) {
		long v = ns_inum("/proc/self/ns/mnt");
		printf("\n== fork() 的子进程 (PID %d) ==\n", getpid());
		printf("  mnt inum = %lu → 与父进程共享 mount ns? %s\n",
		       v, v == my_mnt ? "YES" : "NO");
		printf("  pid inum = %lu (PID namespace 共享, 但 PID 编号不同)\n",
		       ns_inum("/proc/self/ns/pid"));
		fflush(NULL);
		_exit(0);
	}
	waitpid(child, NULL, 0);

	printf("\n== 打开 /proc/self/ns/mnt: 它是 nsfs 文件系统里的一个 inode ==\n");
	system("ls -l /proc/self/ns/mnt");
	return 0;
}

/* vfschain.c — 把一条路径的每一级"串"出来 */
#define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>

#define MAXLVL 64

int main(int argc, char **argv)
{
	const char *path = (argc > 1) ? argv[1] : "/home/charles/vfslab/a.txt";
	if (path[0] != '/') { fprintf(stderr, "需要绝对路径\n"); return 1; }

	char tmp[1024];
	snprintf(tmp, sizeof(tmp), "%s", path);
	char *comps[MAXLVL];
	int n = 0;
	char *save = NULL;
	for (char *c = strtok_r(tmp, "/", &save); c; c = strtok_r(NULL, "/", &save))
		comps[n++] = c;

	printf("路径: %s\n", path);
	printf("== 正向: 从 / 逐级 openat 下钻 (内核 link_path_walk 的缩影) ==\n");

	int dirfds[MAXLVL];	/* 各级目录 fd 保留, 供反向 ".." 验证 */
	int ndirs = 0;

	int fd = open("/", O_PATH | O_DIRECTORY);
	dirfds[ndirs++] = fd;
	struct stat st;
	fstat(fd, &st);
	unsigned prev_maj = major(st.st_dev), prev_min = minor(st.st_dev);
	printf("  [0] \"/\" %*s inode=%-8lu dev=%u:%u  目录\n", 14, "",
	       (unsigned long)st.st_ino, major(st.st_dev), minor(st.st_dev));

	for (int i = 0; i < n; i++) {
		int is_last = (i == n - 1);
		int nfd = openat(fd, comps[i], O_PATH | (is_last ? 0 : O_DIRECTORY));
		if (nfd < 0) { perror(comps[i]); return 1; }
		fstat(nfd, &st);

		int newdev = (major(st.st_dev) != prev_maj || minor(st.st_dev) != prev_min);
		printf("  [%d] \"%s\"%*s inode=%-8lu dev=%u:%u  %s%s\n",
		       i + 1, comps[i],
		       (int)(14 - (int)strlen(comps[i])), "",
		       (unsigned long)st.st_ino, major(st.st_dev), minor(st.st_dev),
		       S_ISDIR(st.st_mode) ? "目录" : "文件",
		       newdev ? "   ← 设备号变了!" : "");

		if (S_ISDIR(st.st_mode))
			dirfds[ndirs++] = nfd;	/* 注意: 不 close, 否则 fd 号会被复用 */
		prev_maj = major(st.st_dev);
		prev_min = minor(st.st_dev);
		fd = nfd;
	}

	printf("\n== 反向: 用 openat(\"..\") 走回 / (dentry->d_parent 链) ==\n");
	int cur = (S_ISDIR(st.st_mode)) ? ndirs - 1 : ndirs - 2;
	for (int i = cur; i >= 0; i--) {
		fstat(dirfds[i], &st);
		int match = 0;
		if (i > 0) {
			int p = openat(dirfds[i], "..", O_PATH | O_DIRECTORY);
			if (p >= 0) {
				struct stat ps, qs;
				fstat(p, &ps);
				fstat(dirfds[i - 1], &qs);
				match = (ps.st_ino == qs.st_ino);
				close(p);
			}
		}
		printf("  [%d] inode=%-8lu dev=%u:%u  %s\n",
		       i, (unsigned long)st.st_ino,
		       major(st.st_dev), minor(st.st_dev),
		       match ? "\"..\" 正好命中上一级 → d_parent 链成立"
			      : (i == 0 ? "(根)" : "\"..\" 检查"));
	}
	return 0;
}

总结

  • super_block 是文件系统实例的"户口本"，内存版（fs.h:1446）与磁盘版（ext4_super_block）通过 buffer_head 桥接，s_bdev/s_fs_info 分别连向设备和私有数据。
  • inode 是文件本体的"身份证"，i_ino 定位磁盘 inode 表（__ext4_get_inode_loc 的三段除法），i_data/i_mapping 把文件接到页缓存，i_block[15]/i_data[15] 承载 extent 树，实现 lblk→pblk（ext4_map_blocks）。
  • dentry 是路径名的缓存：d_parent/d_children 组成树，d_hash 提供哈希查询，d_inode/d_alias 把名字接到 inode，d_sb 把每个名字归属到文件系统。
  • file 是进程的打开会话：f_path 记住解析结果，f_pos 记住当前位置，f_op 承载读写方法；files_struct 用一张表把进程 fd 和 file 串起来。
  • 磁盘关联是一条四层通道：偏移 >> blkbits → lblk → ext4_map_blocks → pblk → (pblk<<k) 扇区 → bio → submit_bio，中间页缓存（address_space/XArray/folio）与 buffer_head 是内存侧的两大缓冲。
  • namespace 隔离的是"视图"而非"数据"：nsproxy->mnt_ns 里的 mount 树（copy_mnt_ns/copy_tree 克隆）决定你看到哪些挂载，但 super_block/inode 全局共享；fs_struct 的 root/pwd 决定路径解析的起点；ns_common.inum 则是命名空间的身份证，/proc/pid/ns/mnt 的 inode 号可用来判断两个进程是否共享挂载视图。

super_block 回答"哪个文件系统"，inode 回答"哪个文件"，dentry 回答"哪个名字"，file 回答"哪个会话"；页缓存与块映射把这一切接到磁盘，mnt_namespace 与 fs_struct 把这一切挂到进程。
